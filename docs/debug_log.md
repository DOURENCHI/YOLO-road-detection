## 2026-10-13 · 训练报 `missing path`，训练根本起不来

**现象**

从项目根目录启动训练，报错：

```
missing path '...\YOLO_Road_Detection\valid\images'
```

但 `datasets/road-traffic-detect/valid/images` 明明存在。

**原因**

`data.yaml` 里写的是 `path: .`（04 号脚本自动生成的默认值）。
Ultralytics 解析相对 `path` 时按**进程当前工作目录**算，不是按 yaml 所在目录算。

在项目根启动 → 它找 `项目根/valid/images` → 那里没有 `valid` 目录 → 报错。

**处理**

把 `datasets/road-traffic-detect/data.yaml` 的 `path` 改成**绝对路径**。

**验证**

训练正常启动，产出 `runs/.../road_baseline/`。

**现状**

**这个坑仍会复发**：`04_convert_labels_to_detection.py` 生成的 yaml 写的还是 `path: .`。
重跑第 4 步之后必须手动改回绝对路径。已在 README 6.2 明确标注。

## 2026-10-13 · 训练产物路径套了两层 `runs`

**现象**

训练产物出现在 `runs/detect/runs/road_baseline/`，多了一层 `runs`。

**原因**

Ultralytics 的输出目录 = **当前工作目录 + `project` + `name`**。
那次启动时工作目录已经在 `runs/detect` 里，于是 `project=.\runs` 又被套了一层。

**处理**

产物保留在现有位置（不影响使用），并在 README 说明路径成因。
更早一次失败尝试留下的半个目录 `runs/detect/runs/detect/road_baseline/`
（只有 `args.yaml`，`weights/` 是空的）在 2026-10-14 移入回收站。

**验证**

删除前先把里面的 `args.yaml` 归档成 `docs/args_failed_run_2026-10-13.yaml`——
那份文件是"为什么会有这个空目录"的唯一证据，删了就没依据了。

**现状**

已清理。**教训**：训练前先确认当前工作目录，或者干脆用绝对路径写 `project`。

## 2026-10-14 · 根目录多出一份重复的 `yolo26n.pt`

**现象**

项目根目录出现 `yolo26n.pt`，而 `weights/` 里已经有一份。

**原因**

Ultralytics 只按命令里写的路径找权重，**找不到就自动下载一份到当前目录**。
命令里写 `model=yolo26n.pt` 而当前目录没有，它就又下了一份。

**处理**

先确认 md5 与 `weights/` 里那份一致，再移入回收站。之后命令统一写
`model=weights/yolo26n.pt`。

**验证**

md5 比对一致才删，避免删掉唯一正确的权重。

**现状**

已解决。**习惯**：权重路径一律写全，避免重复下载。

## 2026-10-14 · `best.pt` 与 `last.pt` 字节数相同，误以为内容一样

**现象**

两份权重都是 5,469,061 字节，看起来应该完全一致。

**原因**

第 48 轮指标最好（`fitness` 最高）成为 `best.pt`，之后又跑了 2 轮到第 50 轮。
权重数值变了，但序列化后的**字节数没变**。

md5 不同：`974c53ee…` / `e56d3064…`。

**处理**

比较权重一律用 md5 或哈希，不看文件大小。

**验证**

md5 明确不同，说明确实是两次不同的权重。

**现状**

已写入 README 6.3 作为通用提醒。

## 2026-10-14 · 改了标签没删 cache，训练读的还是旧数据

**现象**

修改了 `datasets/road-traffic-detect/` 下的标签文件，重新训练，结果毫无变化。

**原因**

YOLO 第一次读数据后会在标签目录生成 `train.cache` / `val.cache`，
里面是解析好的标签索引。训练直接读缓存，不看 `.txt`。

**处理**

```bash
rm datasets/road-traffic-detect/train/labels/train.cache
rm datasets/road-traffic-detect/valid/labels/val.cache
```

**验证**

删缓存后重新训练，指标发生变化。

**现状**

已写入 README 6.1 作为固定检查项。

## 2026-10-14 · 空标签文件：标是漏了还是本来就没有目标

**现象**

`datasets/road-traffic-detect/valid/labels/` 里有一个 0 字节标签文件：

```
1653753597698_jpg.rf.830c9b5213f4259a90da83dd73551633.txt
```

空标签可能是"这张图确实没有目标"，也可能是**漏标**。脚本判断不了。

**原因**

校验脚本只能证明格式合法，不能证明"该标的都标了"。

**处理**

写了 `visualize_labels.py`，专门把空标签对应的原图放大输出
（`results/label_check/empty_label_check.png`），人眼判断。

**验证**

人工核实：画面里**有一辆载两人的摩托车没被标**，**判定为漏标**。

**现状**

已知数据缺陷，1 张图。不改数据集（改了会让指标不可比），但在文档里如实记录。

## 2026-10-14 · 数据泄漏检查：内容干净，但时间戳完全重叠

**现象**

需要确认 train / valid / test 之间有没有重复图片。

**原因**

如果测试集里混了训练集的图，报出来的 mAP 就是虚高的。

**处理**

写 `check_data_leakage.py` 做三重检查（md5 / dHash / 时间戳邻域）。

**验证结果**

| 检查 | 结果 | 解读 |
|---|---|---|
| 内容 md5 | 跨划分 **0 对** | 没有完全相同的文件 |
| dHash（阈值 5） | 跨划分 0 对；最接近一对距离 **15** | 没有画面近似的重复；距离 15 说明检查有区分度 |
| 时间戳 | 三划分跨度**完全重叠**（2022-05-23 ~ 2022-07-01），最近一对隔 **4.9 秒**，1 分钟内 **158 对** | 可能是同一段采集被随机切到不同划分 |

**结论必须分两句说**：

- 内容层面：**干净**，没有重复
- 划分方式：**按图随机切**，存在轻度场景重叠的风险，测试指标要按**偏乐观**理解

时间戳靠得近只是**弱证据**，不等于画面重复。这句边界不能省，
否则就是把检查结果说过了头。

**现状**

**已知边界**。待办里已列"补一条场景级去重办法（按采集批次分组后再划分）"，
并注明：**重新划分后现有指标不能直接对比**，必须重新评估并标注「旧划分下的结果」。

## 2026-10-14 · 类别严重不均衡：总体 mAP 好看不代表每类可靠

**现象**

评估后逐类看，`tractors` 的表现明显差于其他类别。

**原因**

数一下框数就清楚了：

| 类别 | train | test |
|---|---|---|
| `vehicles` | 763 | — |
| `tractors` | **1** | **0** |

训练集只有 1 个样本，测试集一个都没有——这一类**根本无法评估**。

**处理**

`05_validate_detection_dataset.py` 打印每个类别的框数，把不均衡变成可见的数字；
`09_evaluate.py` 的 `metrics_per_class.csv` 同时列出"训练集框数"和"测试集框数"两列，
让读者能自己判断某一类的指标可不可信。

**验证**

逐类 AP 柱状图上 `tractors` 那根柱子缺失或极低。

**现状**

**数据集固有问题**，不通过调参解决。文档里明确写出：
"总体 mAP 好看，不代表每个类别都可靠。"
