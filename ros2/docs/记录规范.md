# ROS2 部署实测：怎么记录、怎么给我、怎么变成项目文档

这份文件解决三个问题：**跑的时候记什么** → **怎么让我拿到** → **最后怎么沉淀成项目成果**。

---

## 一、核心机制：日志写在 D 盘，我直接读

WSL2 的 `/mnt/d` 就是 Windows 的 D 盘。项目在：

```
Windows: D:\VC Code\YOLO_Road_Detection\
WSL:     /mnt/d/VC Code/YOLO_Road_Detection/
```

所以日志只要写进 `ros2/runlogs/`，**我在 Windows 侧能直接打开，你不需要复制粘贴终端输出**。
这是整套方案的关键——省掉你最烦的那步。

---

## 二、每次开一个 WSL 终端，先做一次这件事

```bash
source "/mnt/d/VC Code/YOLO_Road_Detection/ros2/tools/runlog.sh"
```

看到 `runlog 已加载` 就对了。然后用 `log` 代替直接敲命令：

```bash
# 格式：log <标签> <原来要跑的命令...>
log A1-compile colcon build --packages-select yolo_trt_ros --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
log A1-check  ros2 topic hz /yolo_trt_node/detections
log A2-start  ros2 launch yolo_trt_ros yolo_trt.launch.py detector:=ort ep:=cpu
```

**标签命名规则**（按教程的五关）：

| 前缀 | 含义 | 典型标签 |
|---|---|---|
| `E` | 环境体检 | `E-os`、`E-ros2`、`E-docker` |
| `B` | 编译 | `B-colcon`、`B-test` |
| `A1` | dummy 检测器 | `A1-compile`、`A1-echo`、`A1-image` |
| `A2` | ORT CPU | `A2-start`、`A2-latency` |
| `A3` | CUDA | `A3-ep`、`A3-latency` |
| `A4` | TensorRT | `A4-build`、`A4-latency` |
| `A5` | 线程对比 | `A5-v1`、`A5-v2` |

每条命令会自动生成：

```
ros2/runlogs/2026-11-24/
├── A1-compile_143512.log   ← 命令 + 环境 + 完整输出 + 退出码
├── A1-check_144003.log
└── INDEX.md                ← 本次所有命令的清单
```

---

## 三、哪些命令必须记录（按优先级）

**必须记**（这些是我判断进度的依据）：

1. 所有编译命令及其完整输出（失败时报错全文尤其重要）
2. `ros2 topic hz /yolo_trt_node/detections` —— 验证帧率
3. `ros2 topic echo /yolo_trt_node/latency --once` —— 延迟数据
4. `ros2 topic echo /yolo_trt_node/detections --once` —— 检测框
5. 任何报错（不管看起来多小）

**可以只说结果**：

- `ls`、`cd`、`cat` 这类查看命令
- 成功的 `source install/setup.bash`

**卡住时的正确做法**：把那条命令用 `log` 重跑一次，然后告诉我标签，我去读日志。
**不要**只发一句"报错了"或截图的一角——我拿不到完整信息就只能猜。

## 四、每关跑完，补一份结构化小结

日志是原始材料，但直接进项目文档太乱。每关做完后，在
`docs/ros2/` 下建一个 JSON（我也能帮你生成，你把数字给我即可）：

**文件名**：`A1_dummy.json`、`A2_ort_cpu.json`、`A3_cuda.json`、`A4_trt.json`、`A5_threads.json`

**格式**（与现有 `docs/deployment/*.json` 保持一致）：

```json
{
  "生成时间": "2026-11-24 15:20:11",
  "阶段": "A1 · dummy 检测器",
  "环境": {
    "WSL": "Ubuntu 22.04",
    "ROS2": "Humble",
    "ORT": "1.22.0",
    "检测后端": "dummy"
  },
  "参数": {
    "detector": "dummy",
    "fps": 10,
    "image_topic": "/camera/image_raw",
    "use_sim_time": false
  },
  "结果": {
    "detections_hz": 10.2,
    "帧数_total": 305,
    "dropped_stale": 0,
    "固定框": {"x1": 240, "y1": 240, "x2": 400, "y2": 400}
  },
  "状态": "通过 / 部分通过 / 失败",
  "证据": ["A1-check_144003.log", "A1-echo_144510.log"]
}
```

"证据"数组里写日志文件名——这样每个数字都能回溯到原始输出，和项目其他文档一个标准。

## 五、最后怎么变成项目成果

三样东西，缺一不可：

### 1. 实测 JSON（上面第四节）
放 `docs/ros2/`。这是"数字从哪来"的答案。

### 2. 实施记录（类似现有的 `docs/deployment/README.md`）
放 `docs/ros2/README.md`，按你一贯的四段式写每一步：

```
## A1 · dummy 检测器：只验证通信

### 做什么
（一句话）

### 为什么这么做
（原理，比如为什么 depth=1 是背压而不是丢帧）

### 怎么操作
（命令，带真实日志文件名）

### 看到什么数据 / 怎么读
（数字 + 判据 + 反直觉的地方）

### 踩的坑
（现象 → 原因 → 怎么定位 → 怎么验证 → 现状）
```

**关键**：改完的部分标成「**实录**」，没做的标成「**预判**」。
现在教程里 A1–A5 全是预判，你跑通一个就升级一个——这是这份工作最大的价值。

### 3. 回填全景手册
把 3C 部分里"未编译验证"改成实际结果，并把实测数字补进附录 A。
手册是从四份源文档生成的（构建脚本 `教学文档/YOLO_Road_Detection/_work/build_merge.py`），
改的时候记得改源文档再重建，别只改成品。

## 六、面试价值：这套记录本身就是作品

面试官问"你做过部署吗"，最有说服力的不是一句"做过"，而是：

> "我在 WSL2 里按 A1–A5 五关验过，这是每一关的原始日志、实测 JSON 和踩坑记录。
> A4 那关我一开始以为是 TensorRT 没生效，后来发现是 ORT 静默回落——日志在这里。"

所以：**日志别删，报错别删**。你以为丢脸的那些失败输出，恰恰是最值钱的部分。

## 七、现在怎么开始

1. 打开一个新的 WSL 终端
2. `source "/mnt/d/VC Code/YOLO_Road_Detection/ros2/tools/runlog.sh"`
3. 按教程第 3 章环境体检开始跑，每条命令前面加 `log`
4. 跑完告诉我，`小T 读 ros2/runlogs/` 里的日志，帮你判读下一步
